# Exercise: Cloud Agent

---

## What You'll Learn
By the end of this demo, you will:
- [ ] Use `/chronicle standup` to generate an activity report for the last 5 days
- [ ] Create a feature issue using Copilot's `/create-issue` slash command
- [ ] Review Copilot-generated pull requests and session details

**Estimated Time:** 15 minutes hands-on; allow 30-45 minutes including cloud-agent execution

## Before You Start

- Sign in to GitHub with an account that has access to Copilot cloud agent.
- Confirm **Issues** and Copilot cloud agent are enabled for the repository.
- Confirm you have write access to the repository.

## 🎯 Step 1: Generate a Standup Report with `/chronicle standup`

1. Go to the GitHub repository for the Photo Gallery & Portfolio application.
2. Select the **Agents** tab in the repository navigation bar. If the tab is not visible, open [github.com/copilot/agents](https://github.com/copilot/agents) and select this repository.
3. Open a new agent task for this repository.
4. Type the slash command:

```text
/chronicle standup --days 5
```

5. Review the generated report for work completed in the last 5 days.
6. For an extra challenge, look through the other slash commands available in the Copilot panel and try them out.

## 🛠️ Step 2: Create a Feature Issue via Copilot Slash Commands

1. Confirm you are in the GitHub repository for the Photo Gallery & Portfolio application.
2. Click the Copilot logo in the top-right next to the search bar.
3. Look through the available slash commands in the Copilot panel by typing `/` and scrolling through the list.
4. Use the following command to draft a new feature issue:

```markdown
/create-issue Add photo download support to the gallery app. Keep the implementation modular, TypeScript-friendly, and consistent with the existing UI. Include loading and error states, use async/await for I/O, avoid hardcoded secrets or URLs, and follow existing project conventions.
```

5. Look over the issue draft generated by Copilot
6. Assign the issue to **Copilot** for this walkthrough. Claude and Codex may use different timeline labels or session views.

## 📚 Step 3: Review Copilot's Changes

1. Stay on the issue page and scroll to **Activity**.
2. Wait for the timeline event **Copilot linked a pull request that will close this issue**, then click the pull request card directly below it.
   - This is an automatic timeline event, not a button named "Selected Agent."
   - The pull request initially appears as a draft and may have no changed files while Copilot is still working.
3. On the pull request's **Conversation** tab, find the **Copilot started work** event and select **View session**.
   - You must be signed in to view the session log.
   - You can also find the session on [github.com/copilot/agents](https://github.com/copilot/agents).
4. Return to the pull request. When Copilot has pushed its implementation, select **Files changed**.
   - If the tab shows **Files changed (0)**, Copilot has not pushed the implementation yet. Wait and refresh the page.
5. Review the diff, the pull request summary, and the validation Copilot reports before deciding whether to merge.

_If time permits, open the PR in GitHub Copilot app and test out the changes made by Copilot._
